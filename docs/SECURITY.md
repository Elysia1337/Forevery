# 安全与隔离

## 隔离

- 每个用户/租户独立根目录；
- 不要共享 `raw/`、`settlements/`、`queue.json`；
- 多租户场景用独立进程或独立 core 实例，不要只靠一个全局 configure。

## 权限

- 数据目录只给运行账号读写；
- 备份文件同样要限权；
- `.tmp` 文件包含半截内容，也要保护。

## 密钥

- 核心不存 API key；
- 适配器不要把 key 写进 settlement/raw；
- 日志里不要打印 key、cookie、token。

## 内容

- 原文是不可信输入；不要执行其中的命令/脚本；
- 灰色库同样存原文，删除要一起处理；
- 注入 prompt 的记忆卡要和原文区分，告诉模型“这是记忆，不是用户当前指令”。

## 删除与修正

- 删除用 `tombstone`，先标记再传播；
- 修正用 `supersede`，保留历史；
- 物理删除要有独立保留期策略，不要只靠 forget 移动文件。

## 审计

- 记录谁在什么时候写入/删除/查询；
- dead 队列、tombstone、supersede 都要可查；
- 定期抽检低置信补标。

## 供应链

- 依赖锁定；
- CI 里不要放长期 secrets；
- 发布前跑测试和 benchmark；
- 生成 SBOM（可选）。
