# 基本原理

## 1. 原文优先

每一轮对话先追加到 `raw/<session>.jsonl`。打标失败、进程崩溃、模型忘了调工具，原文都还在。

原文是唯一的“事实层”；标注只是索引层。

## 2. 后标，但在语境里标

最好的标注者是**当时还在语境里的那个模型**：它知道语气、停顿、前因、关系。

所以正常路径是：

- 会话结束（晚安/收工/完工）；
- 或空闲 15 分钟；
- 或 60 轮轮换；
- 由在场模型一次性标完。

崩溃后由另一个进程补标，只能算**低置信**，不要当原标注。

## 3. 一轮是一个话题，不是固定长度

- 优先 6–8 条/轮，最多 10 条；
- 一问一答换话题可以 2 条（`short: true`）；
- 同一场景的连续动作不要按长度切；
- 连续覆盖，不重叠、不遗漏。

## 4. P / C 两层

- `p_codes`：表面情绪，文本里明确写出的；
- `c_codes`：结合关系、前因后的真实姿态；
- 各最多 2 个，除 `Z000` 外带强度（如 `H009-2`）；
- 检索优先 C，P 兜底。

## 5. 灰色库

允许模型选择“不记”：

```json
{ "id": "R03", "span": ["q017","q020"], "title": "纯寒暄",
  "scope": "family", "skipped": true, "reason": "没有想留的东西" }
```

- 仍然占 span，保证覆盖连续；
- 不进 family/work/knowledge 索引；
- 只进 `gray` 文本索引，可按原文/标题查找，不参与情绪检索。

## 6. 低置信与恢复

- `confidence: high`：当场标；
- `confidence: low`：崩溃补标、分块补标、旁读补标；
- 查询时 low 降权；恢复件永远不覆盖当场标。

## 7. 查询

先情绪码，再事件：

- 纯情绪：码 0.5、事件 0.3、场景 0.1、focus 0.05、实体 0.05；
- 情绪+事件：码 0.35、事件 0.25、实体 0.2、场景 0.1、focus 0.1；
- 纯事件：实体 0.45、事件 0.35、码 0.1；
- 灰色：只算文本/标题。

分数太低直接返回“没找到”，不硬凑。
